  - Research 2026-10-27 (orchestrator):
    - Vite's performance guide says to avoid barrel files: importing one name from a barrel makes the dev server fetch and transform every file behind it (vite.dev/guide/performance). `lucide-astro` 0.556 is a barrel of 1,884 `.astro` icons, imported in 12 files for about 36 icons. The same pattern is reported for Tabler icons (tabler/tabler-icons#1133). Lucide recommends per-icon imports.
    - Cheapest fix: `lucide-astro` already exposes per-icon paths (`exports['./*'] → dist/*.astro`), e.g. `import Instagram from "lucide-astro/Instagram"`. No new dependency. Optional later: move to the official `@lucide/astro` package (new dependency → Julio's OK).
    - The site uses `<ClientRouter />` (`src/layouts/Layout.astro:222`): a click waits for the whole next page before swapping, so on-demand compilation shows up as a pause after the click.
    - `platformProxy.enabled: true` (`astro.config.mjs`) runs the local Cloudflare runtime for every SSR request; measure with it on and off.
    - Vite `server.warmup` can pre-compile frequently used files at dev start. The project is on Astro 5.10.1; Astro 7 (June 2026) brings a Rust compiler, so an upgrade is a separate, larger step (two majors).
  - Output: numbers + fix, or a measured case for C3.
